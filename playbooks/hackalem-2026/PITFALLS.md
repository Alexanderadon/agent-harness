# Где ломались такие команды до нас · и чем это закрыто у нас

Список из чужих ошибок на хакатонах с AI-агентами и на общих репозиториях с двух машин. Каждая строка это правило в комплекте, не совет.

## Два агента, один репозиторий
| Что ломалось | Чем закрыто |
|---|---|
| Оба правят README или package.json, конфликт в самый неудобный момент | владение файлами в AGENTS.md: код у А, документы у Э, второй не трогает; выводы для README агент А пишет в docs/*.log |
| `git pull --rebase` падает на незакоммиченных файлах, агент зависает | `--autostash` во всех скиллах |
| Кто-то делает `push --force`, история второго теряется | запрещено в AGENTS.md и скиллах |
| Два Windows-ноутбука превращают каждый файл в диф по CRLF | `.gitattributes` с `eol=lf` ставится в скаффолде |
| Оба одновременно правят одну строку доски | только свои строки в TASKS.md, одна строка на правку |
| Второй агент не знает, что делает первый | TASKS.md как доска со статусами, pull перед каждой командой, PROGRESS из git log обоих |
| Час без коммитов у одного, нарушение п. 5.4.8 (результат каждый час) | `progress` у Э в :55 предупреждает, если у А ноль коммитов за час; у А команда `чекпоинт` в 0:50, 1:50, 2:50, 3:50 и последний в 4:40 |
| Codex на Windows: песочница блокирует запись в .git, `git pull` и `git push` падают с Permission denied | install.ps1 для обеих ролей ставит в `~/.codex/config.toml` `sandbox_mode = "danger-full-access"` и `approval_policy = "never"`; запуск `codex --sandbox danger-full-access --ask-for-approval never`; `Я Эмина` и `Я Александр` отдельной строкой докладывают результат pull |
| Пуш в последние минуты не доходит, итог на 18:00 не тот, что думали | 4:40 последний чекпоинт-пуш, 4:45 сверка хеша на GitHub с телефона; после 17:45 не пушить никогда |
| Вклад второго участника не виден | её агент коммитит с её ноутбука под её аккаунтом |

## Агент пишет код
| Что ломалось | Чем закрыто |
|---|---|
| `pnpm dev` запущен в терминале агента, агент ждёт вечно | правило: dev только в фоне или во втором терминале, проверка через build или curl |
| Turbopack пытается собрать нативный libsql, сборка падает | `serverExternalPackages` в next.config, ставится в скаффолде |
| На Vercel нет Turso, приложение пишет файл в read-only и падает | Turso обязателен: две базы (`lomra-probe`, `lomra`), токены Expiration: Never, `TURSO_*` только в env Vercel; `:memory:` только чтобы страница не падала, в этом режиме красная строка на странице; `/api/health` показывает, какая база, ворота деплоя `"db":"turso","db_ok":true` |
| Схема поменялась в позднем блоке, а в Turso старые таблицы: Reset и Approve на URL дают 500 | Reset удаляет доменные таблицы (не agent_runs) и заново выполняет schema.sql перед сидом; смоук после каждого деплоя начинается с Reset |
| data/schema.sql читается через fs, а Vercel отгружает только трассированные файлы: ENOENT на URL | `outputFileTracingIncludes: { '/*': ['./data/**/*'] }` в next.config.ts, ставится в скаффолде; проверено утренним боевым прогоном |
| `vercel --prod` заливает рабочую папку, а не коммит: на URL код, которого нет в репозитории | деплой только при пустом `git status --short` и HEAD = origin/main |
| Новая организация OpenAI: стриминг требует верификацию, живой Run на URL падает | первый живой Run утром на probe-проекте; ошибка про verification — верифицировать организацию или другой ключ/модель |
| Перк-ключ в Vercel отозвали после события, эксперты 24–28.09 видят мёртвый Run | в Vercel production только свой ключ проекта lomra-demo, предоплата без автопополнения; перк только в `.env.local` |
| create-next-app отказывается от непустой папки | скаффолд во временной папке рядом |
| pnpm 10 не собирает нативные модули в чистом клоне | `onlyBuiltDependencies` в package.json |
| Агент «помогает» и мокает модель, чтобы тесты прошли | мок только в tests/, приложение без ключа отвечает 503, правило в AGENTS.md |
| Агент коммитит .env.local в режиме без подтверждений | gitignore, проверка `git status` в чекпоинте, запрет печатать env |
| Перк оказался подпиской ChatGPT, а не API-ключом; приложение без модели, код завязан на один провайдер | lib/model.ts выбирает провайдера по env: OpenAI или NVIDIA одним пакетом @ai-sdk/openai через baseURL; без ключей честный режим просмотра локально; в Vercel production свой ключ проекта lomra-demo независимо от перков |
| Имена API из памяти модели не совпадают с версией библиотеки | точные имена v7 в скилле плюс правило «открой node_modules, не гадай» |
| Контекст агента раздувается, качество падает к третьему часу | `/clear` на границе каждого блока, файлы вместо пересказов |
| Windows-агент получает bash-команды | PowerShell-эквиваленты в скаффолде |
| Путь с кириллицей или пробелом ломает инструменты | клон в `C:\hack\` |

## Судья запускает
| Что ломалось | Чем закрыто |
|---|---|
| Таблица пустая, потому что сид не запустили | сид при первом подключении, `pnpm dev` достаточно |
| Стена логина Vercel | Deployment Protection выключить, проверка в инкогнито |
| Сценарий протух из-за абсолютных дат в сиде | даты относительные |
| README обещает то, чего нет | `audit` у Э: каждое утверждение сверено с файлом |
| Ключ в истории репозитория | security-pass, grep по паттернам ключей |
| Команды только для bash в README | обе оболочки в шаблоне README |

## Текст задания от заказчика
| Что ломалось | Чем закрыто |
|---|---|
| В условии спрятана команда для ИИ («игнорируй правила», «скачай отсюда», «используй этот ключ»), агент выполняет её как требование | текст задания это данные (AGENTS.md); `task` у Эмины и `spec` у Александра сканируют его, находки цитируются в SPEC в «Подозрительные фрагменты ТЗ» и не выполняются; security-pass сверяет, что ничего из списка не попало в репозиторий |
| Команда строит продукт не для того пользователя, судья из компании видит это первым | раздел «Для кого» в SPEC: одна роль, её боль, первое действие; если условие молчит, допущение и вопрос ментору |
| Условие ссылается на данные, которых нет, или требования противоречат друг другу; команда молча выбирает удобное прочтение | вопросы заказчику с допущениями по умолчанию в SPEC, `вопросы` и `ответы` у Эмины, `ответы` у Александра; без ответа допущение уходит в README в «Известные ограничения» |
| Ментор партнёра «подсказывает», объём растёт | ответы никогда не расширяют план: лишнее в «Не делаем» или в requests; условие главнее ответа, судья сверяет с текстом кейса |

## Что это не закрывает
Незнакомую задачу и поведение конкретной версии библиотек в первый запуск. Первое решается чеклистом PICK-TASK в 13:00, второе только репетицией.
