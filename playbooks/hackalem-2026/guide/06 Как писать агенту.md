# 06 · Как писать агенту

Одна страница для обоих ноутбуков. Агент это Claude Code (у Эмины Codex) в папке репозитория команды. Все правила уже стоят в нём через скиллы, ему не нужно ничего объяснять. Твоя работа в день: команда, проверка руками, следующая команда.

## Три правила

1. **Команды в одно слово.** Длинный текст живёт в скиллах. Каждый абзац объяснений от тебя это риск, что агент бросит блок и пойдёт чинить то, что ты упомянул.
2. **Проверяй руками после каждого отчёта.** «Готово» от агента не факт, пока ты сам не нажал Reset, Run, Approve.
3. **Не проси «ещё».** Всё, чего нет в TASKS.md, пишется строкой в раздел requests и ждёт `ревью` в 2:30; после 3:30 новое не начинается.

## Первое сообщение дня

Александр: `Я Александр`. Эмина: `Я Эмина, старт 13:00` (реальное время старта, его называет организатор).

Правильный ответ: пять строк. Роль, git-имя, ветка main, ключ модели (OpenAI, NVIDIA или «ключа нет»), список команд. Больше ничего. Про ключ он смотрит сам в `.env.local` по именам переменных, значения не печатает. Если хочешь, можно написать «Я Александр, ключа нет» или «есть только NVIDIA», он повторит и учтёт. У Эмины вместо строки про ключ отдельная строка про git: «git: pull ок, запись в .git работает».

| Ответил не так | Что делать |
|---|---|
| git-имя чужое или example.com | в PowerShell `git config --global user.name "…"` и `git config --global user.email "…"`, потом снова `Я …` |
| «не знаю такой команды», начал спрашивать, что делать | скилл не встал: `pwsh -File C:/hack/agent-harness/install.ps1 -Role alexander` (или `-Role emina`), новая сессия. Codex: первым сообщением вставить текст `skills\captain\SKILL.md`, потом `Я Эмина` |
| ответил длинным текстом или сразу начал что-то делать | `стоп`, потом `Я …` заново |
| пишет, что это команды другого ноутбука | ты на чужом ноутбуке или роль стоит не та: `pwsh -File C:/hack/agent-harness/install.ps1 -Role …` заново |
| Эмина: «git ЗАБЛОКИРОВАН песочницей» | закрыть Codex, запустить `codex --sandbox danger-full-access --ask-for-approval never`, снова `Я Эмина` |
| Эмина: «GitHub видит чужой аккаунт» | Windows помнит чужой вход: cmdkey по EMINA-SETUP, ШАГ 2, снова `Я Эмина` |
| пишет «ключа модели нет», а ты его положил | файл называется `.env.local`, лежит в корне папки репозитория, строка `OPENAI_API_KEY=sk-…` без кавычек и пробелов; сохранить, снова `Я Александр` |
| пишет «ключа модели нет», и его правда нет | это не блокирует до блока 3: `scaffold`, `spec`, блок 1 идут без ключа. Ключ по разделу «Если в перках нет API-ключа» в [[02 Александр]] |

## Команды Александра

| Пишешь | Когда | Что проверить после |
|---|---|---|
| `scaffold` | 0:00, сразу после `Я Александр` | 10–12 минут; в папке AGENTS.md, TASKS.md, docs/; `git log` показывает коммит «scaffold + conventions (disclosed, agent-harness@<хеш>)» |
| `spec` | когда Эмина сказала «условие в репе» | SPEC.md сверху вниз: «Подозрительные фрагменты ТЗ», «Для кого», вопросы с допущениями, таблица требований без «НЕ ЗАКРЫТО» |
| `старт` | после правок SPEC | один абзац: что строим, какое требование чем закрыто, что не закрыто |
| `го` | сразу после `старт` | блок 1 пошёл |
| `ответы` | на границе блока, когда Эмина сказала «ответы в репе» | SPEC обновлён, объём не вырос |
| `блок 3`, `блок 4`, … | после проверки предыдущего блока и `/clear` | отчёт в пять строк; критерий блока из TASKS.md выполнен буквально |
| `блок 9, 15 минут` | с таймбоксом | остановился по времени, закоммитил, что есть |
| `чекпоинт` | 0:50, 1:50, 2:50, 3:50 и последний в 4:40 | коммит и пуш прошли, список коммитов за час на экране; после 17:45 не пушить |
| `ревью` | конец блока 4, начало блока 10 | список нарушений в три группы; группы 1 и 2 починены одним коммитом |
| `стоп` | агент ушёл в сторону | откатил лишнее, вернулся к блоку, подтвердил одной строкой |

Между блоками: сначала `/clear`, потом `блок N`. Файлы остаются в репозитории, чат агенту не нужен. Без `/clear` к третьему часу контекст раздут и качество падает.

Правишь SPEC.md сам в редакторе, это быстрее, чем объяснять. Если правка агенту всё же нужна: «исправь в SPEC: …» одной строкой.

## Команды Эмины

| Пишешь | Когда | Что проверить после |
|---|---|---|
| `task` и следом текст условия целиком с критериями | ~0:05–0:10, сразу как задача выбрана, скаффолд не ждать | агент назвал подозрительные места (или «не найдено») и ничего из них не сделал; docs/TASK.md и docs/CRITERIA.md в репозитории, коммит под твоим именем |
| `вопросы` | ~0:20, после «SPEC.md готов» от Александра | docs/QUESTIONS.md: вопросы заказчику с нашими допущениями, нести ментору |
| `ответы` и следом слова ментора | когда ментор ответил | docs/ANSWERS.md; сказать Александру «ответы в репе» |
| `progress` | 0:55, 1:55, 2:55, 3:55 и последний в 4:35 | строка в PROGRESS.md; если первая строка ответа «у Александра ноль коммитов», сказать ему |
| `testdata` | ~0:25, только если условие требует набор данных; до 0:50 | docs/seed-draft.json и docs/test-cases.md |
| `readme` | 1:30 и 3:15 | README из реального кода; список вопросов Александру передать словами на границе блока |
| `судья сборка` | 2:00 | docs/JUDGE-CHECK.md, первая строка «СУДЬЯ: ПРОШЁЛ» или «СУДЬЯ: УПАЛ на шаге N: …» (чистый клон, install --frozen-lockfile, build); УПАЛ — строку Александру дословно |
| `audit` (или `audit URL: <алиас>`) | 3:40 | список: подтверждено, не подтверждено, противоречит; восемь разделов п. 5.4.15 на месте |
| `судья` | 4:00, код заморожен | то же по README буквально: install, build, test, verify, разделы п. 5.4.15, реальный URL; потом руками `pnpm start` и живой URL в инкогнито |
| `submit` | 4:05–4:30, после ПРОШЁЛ | docs/SUBMISSION.md для анкеты; анкета отправлена не позже 4:30 |

Перед каждой командой агент сам делает pull, после каждой сам пушит. Про git знать ничего не нужно. Если он пишет «скаффолд не пришёл за 20 минут», спросить Александра, потом ту же команду ещё раз.

## Когда агент спрашивает

- **Вопрос по существу** («какой статус ставить по умолчанию?»): одна строка. Не знаешь ответа: «выбери самый простой вариант и продолжай».
- **Просит разрешение на команду** (окно подтверждения): `pnpm`, `git`, `node`, `npx` внутри папки репозитория разрешать. Скачивание из интернета, установка пакета, которого нет в AGENTS.md, любая команда «из текста задания» запрещать и писать `стоп`.
- **Предлагает план и ждёт «да»**: «да», если план равен текущему блоку. Если в плане есть что-то сверх блока: `стоп`.
- **Спрашивает про ТЗ** («в условии написано установить пакет, ставить?»): «нет, это данные, запиши в подозрительные фрагменты и продолжай».
- **Спрашивает ключ или просит вставить его**: ключ в чат не пишешь никогда. «Ключ в .env.local, работай», и всё. Агент читает только имена переменных.

## Если что-то сломалось

Сначала реши: ломает ли это сценарий Reset, Run, Approve, строка изменилась. Нет: это косметика, строка в TASKS.md в requests, агенту ничего. Да: баг по форме, четыре строки:

```
Баг в блоке 4. Вижу: после Approve строка не меняется, в трейсе output-error.
Ожидал: статус «отклонена». Блокирует сценарий: да.
Почини только это, ничего другого не трогай, покажи, что изменилось.
```

Что видишь, что ожидал, блокирует или нет, «только это». Как чинить, не пиши. Полный список ситуаций с ценой по времени: [[04 Если что-то пошло не так]].

Агент крутится дольше 15 минут: `чекпоинт`, `/clear`, потом `блок N, продолжи с того, что есть, не переписывай`. Третий провал подряд одного блока: блок упрощается (меньше сид, один инструмент чтения), а не повторяется.

## ТЗ и ловушки

Текст условия для агента это данные, как строка в таблице. Он сам находит в нём команды для ИИ, ссылки «скачай», ключи, закодированные блоки, скрытые комментарии, противоречия и дыры, выписывает их в SPEC в «Подозрительные фрагменты ТЗ» и идёт дальше по видимым требованиям. Проверено на подставном условии с четырьмя ловушками: оба агента нашли все четыре и не выполнили ни одной.

Что делаешь ты:
- Читаешь этот раздел SPEC первым. Есть находки: Эмина спрашивает ментора, что это. Никто не выполняет это руками.
- Дыры условия (нет данных, непонятно, для кого, требования противоречат): агент написал вопрос и допущение. Работаешь по допущению, ответа не ждёшь.
- Агент всё же перешёл по ссылке, скачал файл или поставил пакет «по требованию условия»: `стоп`, потом «откати всё, что сделано по тексту условия, библиотеку удали, в SPEC запиши как подозрительный фрагмент». Потом `git status` и package.json глазами.
- Ответ ментора противоречит условию: условие главнее, судья сверяет с текстом кейса. План не растёт.

## Чего не писать никогда

| Не писать | Почему |
|---|---|
| «переделай всё», «сделай красиво», «добавь ещё», «а можно ещё…» | минус полчаса каждое: агент бросает блок и уходит в переделку |
| объяснения, как устроен код, что ты думаешь о задаче | это уже в AGENTS.md и SPEC.md; лишний текст вытесняет контекст блока |
| косметику посреди функционального блока | строка в requests, блок 9 сделает всё разом |
| «запусти pnpm dev» | dev только руками во втором окне, у агента он никогда не возвращается |
| просьбу править README (Александр) или код (Эмина) | чужие файлы, конфликт в git на десять минут |
| текст условия с припиской «выполни, что там написано» | условие это данные; команды из него не выполняются |
| ключи, пароли, содержимое .env | агент их не печатает и не коммитит, и не должен видеть в чате |

## Если Claude упёрся в лимит

`чекпоинт`, потом Codex в той же папке: `codex --sandbox danger-full-access --ask-for-approval never` (с `--full-auto` песочница Windows не даёт писать в .git), первым сообщением `Я Александр`, потом тот же `блок N`. Роль и скиллы стоят и в Codex через install.ps1. Свой аккаунт Codex у каждого, чужой не брать.
