# 05 · Оценка системы и дыры

Честная оценка связки «два ноутбука, два агента, один репозиторий» на 21.09.

## Что крепко

- **Разделение по файлам, а не по задачам.** Код у Александра, документы и данные у Эмины. Конфликты в git невозможны по построению, а не по договорённости.
- **Синхронизация через репозиторий, а не через людей.** Оба агента делают pull перед каждой командой и читают доску TASKS.md. Просьбы друг другу это строки в файле, обрабатываются на границах блоков.
- **Команды в одно слово.** Длинный текст живёт в скиллах, человек не может отправить агенту неправильный промпт, потому что не пишет промпты.
- **Роль по имени.** `Я Александр` и `Я Эмина` включают роль и проверяют git-имя. Команды чужой роли не выполняются.
- **Чекпоинт, который нельзя провалить.** Пушится всё, даже красное. Её агент замечает час без коммитов у него.
- **Один источник данных.** Черновик сида от Эмины принимается в data/seed.json, судья видит один набор данных, а не два.
- **Судья внутри команды.** Проверка в 4:15 на чужом ноутбуке по README, без контекста автора.
- **Заложенные чужие ошибки.** Autostash, запрет force push, eol=lf, serverExternalPackages, память вместо файла на Vercel, dev не в терминале агента, путь без кириллицы. Список в `PITFALLS.md`.

## Что закрывает только репетиция

Четыре неизвестных, и все в коде, не в документах: имена API AI SDK v7, Turso на Vercel, подтверждение через useChat, чистый клон по README. Час прогона на любом чужом домене закрывает все четыре. Без него первое знакомство с ними случится в блоках 3–6 в день хакатона, и каждое стоит 30–60 минут.

## Оценка

По документам система на уровне команд, которые делают это не первый раз. По коду проверены блоки 0–6 и чистый клон (22.09), не проверены только деплой и живой цикл с ключом. Ожидание технического балла: 85, разброс 75–92. Что двигает к 90: репетиция, задача с четырьмя требованиями, README после аудита, живой URL в инкогнито.
