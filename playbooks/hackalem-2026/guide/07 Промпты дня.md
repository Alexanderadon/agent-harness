# 07 · Промпты дня: что писать дословно

Почти всё — команды в одно слово: длинный текст живёт в скиллах, агент сам разворачивает команду в процедуру. Ниже каждое сообщение дня дословно, с моментом и тем, что проверить после. Время от старта: `0:00` = 13:00, отсечка 18:00.

Писать агенту своими словами длинные указания не нужно и вредно: «сделай красиво», «исправь всё», «добавь ещё фичу» ломают порядок блоков. Ключи и токены в чат никогда: только в `.env.local` руками или в `vercel env add`.

### Второе окно PowerShell — руками

```
vercel link --yes --project lomra
vercel --prod --yes
```

Первая пара — ~0:25, пустой деплой. Дальше `vercel --prod --yes` только при чистом дереве и HEAD = origin/main (vercel заливает папку, а не коммит). В 0:50, 1:50, 2:50 это проверяет агент на `чекпоинт` («деплой можно»), после загрузки ему `дальше`. В 3:15 (кандидат), 4:00 (финальный) и после каждого фикса 4:00–4:25 чекпоинта нет, проверяешь сам:

```
git status --short
git rev-parse HEAD
git rev-parse origin/main
```

Первая команда ничего не печатает, два хеша равны — деплой. После каждого деплоя, начиная с 0:50:

```
curl -s <алиас>/api/health
```

Ждёшь `"db":"turso","db_ok":true`. Потом телефон в инкогнито: Reset → Run → Approve → строка изменилась → обновить два раза → изменение на месте → Reset.

**1:50, уровень рассуждений.** После деплоя 3 Run на URL, засечь секунды. Все быстрее 15 с — поднять до `medium` (если переменная уже есть, сначала `vercel env rm AGENT_REASONING production --yes`), потом ещё 1 Run; иначе не трогать:

```
vercel env add AGENT_REASONING production
vercel redeploy <алиас> --target production
```

**2:50, выбор модели в Vercel** (sol, если 3 из 3 Run < 30 с с карточкой Approve и баланс ≥ $10; иначе luna; иначе 5.6-terra):

```
vercel env rm AGENT_MODEL production --yes
vercel env add AGENT_MODEL production
vercel redeploy <алиас> --target production
```

После 3:15 модель и env не трогать. После 4:30 никакого `vercel --prod`, только `vercel rollback`.
