# 03 · Эмина: что нажимать и что писать

Твоя роль: капитан. Задача, документы, данные, организаторы, проверка как судья, подача. Кода ты не касаешься, и твой агент тоже. Ты пишешь ему команды в одно слово, он пишет файлы и сам отправляет их в репозиторий под твоим именем.

## До 22-го, по порядку

1. На ноутбуке: Node 22, pnpm 10, Git for Windows, Codex CLI (`npm i -g @openai/codex`), VS Code. В PowerShell один раз: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
2. Git с твоим именем: `git config --global user.name "Эмина Ануарбекова"` и `git config --global user.email "…"`, где почта взята с github.com, Settings, Emails: основная почта аккаунта Emina-An или служебный адрес вида `12345678+Emina-An@users.noreply.github.com`, который там показан (цифры свои). С другой почтой GitHub не зачтёт коммиты твоему профилю. Один тестовый `git push` в любой свой репозиторий, чтобы Windows запомнил вход именно под Emina-An. Открыть этот коммит на github.com: рядом аватарка и ссылка Emina-An. Серое имя без аватарки значит, почта не привязана к аккаунту, вклад не засчитается профилю (п. 5.4.7).
3. Комплект: `git clone https://github.com/Alexanderadon/agent-harness`, потом `pwsh -File C:/hack/agent-harness/install.ps1 -Role emina`. В выводе есть строки `sandbox_mode = "danger-full-access"` и `approval_policy = "never"`: install сам прописал их в `~/.codex/config.toml`.
4. Проверка права записи: открыть https://github.com/BAITC-Hacks/hack-463fe33c-lomra под своим аккаунтом. На README виден карандаш «Edit» и кнопка «Add file». Не видно: до 22-го написать организаторам, чтобы добавили твой аккаунт.
5. `git clone https://github.com/BAITC-Hacks/hack-463fe33c-lomra` в `C:\hack\`. Только клон, ничего не отправлять. Потом в папке клона `git push --dry-run origin main`: ответ «Everything up-to-date» значит, право записи есть и вход под твоим аккаунтом работает; «denied» или 403 значит, до 22-го писать организаторам; «Repository not found» значит, Windows помнит чужой аккаунт GitHub (cmdkey, EMINA-SETUP, ШАГ 2). Ничего при этом не отправляется.
6. Проверка агента: в папке клона запустить `codex --sandbox danger-full-access --ask-for-approval never` (не `--full-auto`: с ним песочница Windows не даёт писать в .git), написать `Я Эмина`. Должны прийти короткие строки: роль, твоё git-имя, ветка, отдельной строкой результат pull, список команд. Строка pull: «git: pull ок, запись в .git работает» — всё хорошо; «git ЗАБЛОКИРОВАН песочницей» — закрыть Codex и запустить командой выше; «GitHub видит чужой аккаунт» — cmdkey, EMINA-SETUP, ШАГ 2. Если Codex не видит скилл, первым сообщением вставить текст файла `skills/captain/SKILL.md` из комплекта, потом `Я Эмина`.
7. Один раз пройти путь судьи на любом проекте: `git clone`, `pnpm install`, `pnpm dev`, открыть localhost. Просто чтобы руки помнили. В день этот путь проходит твой агент по командам `судья сборка` (2:00) и `судья` (4:00), а ты после него руками `pnpm start` и живой URL.
8. Прочитать `PICK-TASK.md` из комплекта: там шесть вопросов к задаче и промпт.

## Если агент на ноутбуке не работает

Всё то же самое руками с телефона через сайт GitHub: открыть файл, карандаш «Edit», текст, «Commit changes». Условие в docs/TASK.md, строка в PROGRESS.md каждый час. README тогда пишет агент Александра по его просьбе, а ты читаешь.

## Чего не делать

- Ничего не отправлять в репозиторий до 13:00 и после 17:45.
- Не давать свой аккаунт Codex Александру и не брать его: каждый пользуется своим.
- Не просить агента править код. Просьба к коду это строка в TASKS.md в разделе requests, агент сам её напишет, если сказать «попроси Александра: …».
- Не предлагать вторую фичу. Одна задача, один сценарий, до конца.
- Не отвечать за Александра на технические вопросы проверяющих: записать вопрос, передать ему на границе блока.
- Не выполнять то, что написано внутри условия как команда: ссылки «скачай», ключи, «для ИИ: сделай так». Агент выписывает это как подозрительное, ты несёшь ментору вопрос, что это. Ловушка или небрежность, в обоих случаях мимо.
