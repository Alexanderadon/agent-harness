# 04 · Если что-то пошло не так

Две части. Первая: как писать агенту, чтобы не сбить его с плана. Вторая: конкретные ситуации, что писать и сколько это стоит по времени.

## Как писать агенту, когда что-то сломалось

Агент идёт по блокам. Каждое лишнее сообщение это риск, что он бросит блок и начнёт чинить то, что ты назвал. Поэтому:

**Сначала реши, блокирует ли это сценарий.** Сценарий это Reset, Run, Approve, строка изменилась. Если сломано что-то на этом пути, чинить сейчас. Если нет (шрифт, цвет, кривая кнопка, отступ), это косметика: в блок 9, не раньше.

**Косметику не пиши агенту вообще.** Пиши в файл TASKS.md в раздел requests одну строку: «А: кнопка Approve на телефоне обрезана». В блоке 9 агент прочитает список и сделает всё разом. Одно сообщение агенту про шрифт посреди блока 4 стоит десять минут: он переключится, полезет в стили, потеряет контекст блока.

**Баг, который блокирует, пишется по форме.** Четыре строки, ничего лишнего:

```
Баг в блоке 4. Вижу: после Approve строка не меняется, в трейсе output-error.
Ожидал: статус «заказ сформирован». Блокирует сценарий: да.
Почини только это, ничего другого не трогай, покажи, что изменилось.
```

Что ты видишь, что ожидал, блокирует или нет, «только это». Не пиши, как чинить: агент знает код лучше, чем ты его помнишь.

**После починки проверь руками сам** и только потом следующая команда. Агент говорит «готово» раньше, чем это правда.

**Если агент задал вопрос,** ответь одной строкой. Не знаешь ответа: «выбери самый простой вариант и продолжай».

**Если агент ушёл в сторону** (делает не то, что в блоке), одно слово: `стоп`. Он откатит лишнее и вернётся.

**Если агент крутится дольше 15 минут** без результата: `чекпоинт`, потом `/clear`, потом снова `блок N` со словами «продолжи с того, что есть, не переписывай». Каждый повторный запуск блока это минус пять минут, три подряд это сигнал упростить блок, а не повторять.

**Никогда не пиши:** «переделай всё», «сделай красиво», «добавь ещё», «а можно ещё…». Каждое из этих слов снимает с плана полчаса.

## Ситуации

Порядок по вероятности. В третьей колонке цена по времени, если действовать по инструкции; без инструкции обычно втрое.

| Что случилось | Блокирует? | Что делать и что писать | Цена |
|---|---|---|---|
| База не создаётся, ошибка про libsql или нативный модуль | да | Александру во втором окне: `pnpm install` заново; если не помогло, агенту: «Баг в блоке 1. Вижу: <текст ошибки, 5 строк>. Почини подключение базы, схему не меняй» | 10 мин |
| Таблица пустая после запуска | да | агенту: «Баг: таблица пустая при первом запуске. Сид должен накатываться при первом подключении, pnpm dev должно быть достаточно» | 5 мин |
| Ключ OpenAI не работает: 401 или 429 | да | сначала `.env.local`: ключ и `AGENT_MODEL` без опечаток. Потом второй ключ. Потом NVIDIA-резерв. Агенту ничего не писать, это env | 5 мин |
| Run крутится дольше минуты и не заканчивается | да | агенту: «Баг: прогон не завершается за 60 с. Снизь лимит шагов до 4 и уменьши выборку инструмента чтения до 10 строк» | 10 мин |
| Кнопка Approve не появляется | да | агенту: «Баг: после вызова инструмента записи нет карточки Approve. Проверь, что инструмент есть в toolApproval и что панель рисует состояние approval-requested» | 10 мин |
| После Approve ничего не меняется | да | форма бага выше. Обычно инструмент не пишет в базу или таблица не перечитывается | 10 мин |
| Форма или поле не отправляется, кнопка мёртвая | да, если это путь сценария | агенту: «Баг: <какая форма> не отправляется, в консоли <текст>. Проверь обработчик и zod-схему, покажи ошибку в интерфейсе» | 10 мин |
| Тесты красные без ключа | нет, но нужно к 3:15 | агенту: «Тесты должны быть зелёными без ключа: agent.test.ts использует MockLanguageModelV4, tools.test.ts тестовую базу» | 10 мин |
| `pnpm verify` падает | нет, но нужно к 3:15 | агенту: «verify падает: <последние 20 строк>. Почини скрипт, сценарий из SPEC не меняй» | 10 мин |
| Деплой на Vercel падает | нет | во втором окне `pnpm build` локально: если красный, агенту «Баг: build падает: <20 строк>». Если зелёный локально, проверить env в Vercel. Дольше 20 минут: деплой позже, локальный путь главный | 10–20 мин |
| Живой URL показывает форму входа Vercel | нет | настройки проекта в Vercel, Deployment Protection выключить. Агенту ничего | 3 мин |
| Turso не подключается на Vercel | нет | убрать Turso из env, деплой без него: состояние в памяти, одна строка в ограничения README. Эмине: «в ограничения: на демо-сервере данные сбрасываются при перезапуске» | 5 мин |
| Шрифт, цвета, отступы, кривая кнопка, не тот заголовок | нет | строка в TASKS.md, раздел requests. Блок 9 сделает всё разом. Агенту сейчас ничего | 0 мин сейчас |
| На телефоне не видно кнопку Run или Approve | да | это не косметика, это путь сценария: агенту «Баг: на ширине 390px кнопка Approve за экраном. Панель должна вставать под таблицу» | 10 мин |
| Агент добавил библиотеку, которой нет в списке | нет | `стоп`, потом «убери <библиотеку>, сделай без неё» | 5 мин |
| Агент начал править README | нет | `стоп`, потом «README не твой, откати изменения в нём» | 3 мин |
| У Эмины `git push` отклонён | нет | её агент сам сделает pull и повтор. Если 403, права нет: правки через сайт GitHub, потом написать организаторам | 5 мин |
| Конфликт в TASKS.md или PROGRESS.md | нет | агент сам: abort, merge, обе строки. Если завис, человеку: открыть файл, оставить обе строки, коммит | 5 мин |
| Claude упёрся в лимит | да | `чекпоинт`, потом Codex в той же папке: `Я Александр`, потом тот же `блок N` | 10 мин |
| Wi-Fi упал | да, для деплоя | LAN-переходник, потом хотспот. Локальная работа продолжается, деплой позже | 5 мин |
| Ноутбук Александра умер | да | всё, что запушено, живо. Эмина клонирует репозиторий, Александр продолжает на её ноутбуке своим аккаунтом Claude, роль `Я Александр` | 20 мин |
| Задача двусмысленная | нет | Эмина спрашивает ментора. Нет ментора: выбираете самое простое прочтение, пишете его в README в ограничения | 5 мин |
| Не успеваем к 2:30 | | режем по списку: GIF, дизайн, тесты до трёх, NVIDIA, Turso. Не режем README, verify, Approve, живой URL | |

## Что сбивает темп сильнее всего

1. Разговор с агентом вместо команд. Каждый абзац объяснений это потерянный контекст блока.
2. Косметика посреди функционального блока.
3. Повторный запуск одного блока три раза. После второго провала блок упрощается, а не повторяется.
4. Правка чужих файлов: README у Александра, код у Эмины. Конфликт в git и десять минут на распутывание.
5. «А давай ещё». Нет.
