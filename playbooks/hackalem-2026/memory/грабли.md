# Грабли: симптом → причина → лечение

Всё ниже реально ломалось при настройке ноутбуков 22–23.09 или на прогонах. Полные тексты — в `../laptops/EMINA-SETUP.txt`, помечены [ГРАБЛИ].

## Установка на Windows
- **`The string is missing the terminator` при запуске .ps1.** Встроенный PowerShell 5.1 читает UTF-8 без BOM как ANSI. Все скрипты комплекта запускать через `pwsh -File ...`. В ~/.codex/AGENTS.md вместо «Роль» видно «Р РѕР»СЊ» — скрипт запускали не через pwsh.
- **`EPERM ... C:\Program Files\nodejs\pnpx`.** `corepack enable` запущен без прав администратора. Нужно окно «Запуск от имени администратора».
- **pnpm 12 вместо 10.** В старой инструкции стояло `pnpm@latest`. Комплект собран на pnpm 10, lock-файлы тоже. Лечение: `corepack prepare pnpm@10.34.5 --activate`.
- **`This: command not found` в git-bash у pnpm, vercel, codex.** Глобальный npm-пакет `node` перекрывает настоящий Node. Лечение: `npm rm -g node`.
- **npm 12 не ставится: `notsup`.** Ему нужна Node ≥ 22.22.2. Лечение: `npm i -g npm@11`, или не обновлять.
- **`remote: Repository not found` на репозитории команды.** Windows помнит чужой вход в GitHub; приватный репозиторий в этом случае выглядит несуществующим. Лечение: `cmdkey /delete:LegacyGeneric:target=git:https://github.com`, потом войти своим аккаунтом. `denied` или 403 — вход свой, но права записи нет: писать организаторам.
- **`dubious ownership`.** Git не доверяет папке. Лечение: `git config --system --add safe.directory C:/hack/lomra` в окне администратора.

## Codex 0.155 на Windows
- **`cannot open '.git/FETCH_HEAD': Permission denied`, при этом `git status` работает.** Песочница выполняет команды от отдельного пользователя CodexSandboxOnline и не пускает в .git. Не лечится ни правами NTFS, ни writable_roots. Лечение: `codex --sandbox danger-full-access --ask-for-approval never`; `install.ps1` ставит это и в config.toml.
- **Агент говорит «чтение файлов подготовки заблокировано» или не знает ничего о команде.** Codex запущен с песочницей (`--sandbox read-only`, `workspace-write`, запуск из приложения или IDE): на Windows она не пускает его даже читать `C:\hack\agent-harness`, где лежит эта память (проверено 23.09). Лечение то же: закрыть и запустить `codex --sandbox danger-full-access --ask-for-approval never`.
- **Агент ведёт себя по старым правилам.** Скиллы лежат в двух папках, `~/.agents/skills` и `~/.codex/skills`, и Codex может открыть старую копию. Признак — в ответ на «Я Эмина» нет отдельной строки «git: pull ок, запись в .git работает». Лечение: в комплекте `git pull`, потом `pwsh -File C:/hack/agent-harness/install.ps1 -Role emina`, потом перезапустить Codex.
- **Агент застрял на удалении папки.** `Remove-Item -Recurse` отклоняется политикой даже при полном доступе. Удалить руками, не бороться. Папки `C:\hack\judge-*` после проверок судьи можно не удалять.
