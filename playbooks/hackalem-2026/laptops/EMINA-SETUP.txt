ШАГ 0.5. POWERSHELL 7 — ОБЯЗАТЕЛЬНО, НЕ ПРОПУСКАТЬ
  [ ] winget install --id Microsoft.PowerShell --source winget --accept-package-agreements --accept-source-agreements
      Проверка (в новом окне терминала):   pwsh -v   -> PowerShell 7.x

  [ГРАБЛИ] Зачем. Встроенный в Windows PowerShell 5.1 читает .ps1 без BOM как ANSI, а install.ps1 в UTF-8
  и с кириллицей внутри. Итог: скрипт падает с "The string is missing the terminator" и НЕ ставит скиллы.
  Симптом легко принять за сломанный комплект. На самом деле сломана кодировка.
  Лечение: всегда запускать скрипты комплекта через pwsh (см. ШАГ 5), а не двойным кликом и не в PowerShell 5.1.
  (Скрипты комплекта теперь сохранены в UTF-8 с BOM и читаются и в 5.1, но документированный путь остаётся pwsh -File.)


ШАГ 1. NODE И PNPM
  [ ] Node.js 22 LTS: https://nodejs.org , установщик по умолчанию.     Проверка: node -v -> v22.x

  [ ] corepack и pnpm 10. Открыть PowerShell ОТ ИМЕНИ АДМИНИСТРАТОРА и выполнить две строки:
        corepack enable
        corepack prepare pnpm@10.34.5 --activate
      Проверка (в обычном окне):   pnpm -v   -> 10.34.5

  [ГРАБЛИ] Два подвоха разом.
  1. corepack enable пишет шимы в C:\Program Files\nodejs и без прав администратора падает с
     "EPERM: operation not permitted, open 'C:\Program Files\nodejs\pnpx'". Нужно именно окно от администратора.
  2. В старой редакции стояло  corepack prepare pnpm@latest  . Сейчас latest это pnpm 12, а весь комплект
     и репетиционное приложение собраны на pnpm 10, lock-файлы от 12 не подойдут. Версию пиннуем руками.

  [ ] Проверка, что не мешает лишний пакет:   npm ls -g --depth=0
      Если в списке есть строка  node@<версия>  — удалить:   npm rm -g node
  [ГРАБЛИ] Глобально установленный npm-пакет "node" (обёртка node-bin-gen) перекрывает настоящий Node.
  В git-bash это выглядит как  "This: command not found"  при запуске pnpm, vercel, codex и claude.
  В PowerShell при этом всё работает, поэтому причину ищут долго.

  [ ] npm НЕ обновлять командой  npm i -g npm@latest .
  [ГРАБЛИ] Текущий npm 12 требует Node >= 22.22.2. На Node 22.20 он откажется ставиться с ошибкой notsup.
  Если обновление нужно:   npm i -g npm@11

  симптом 403 — его можно не дождаться.

  пользователя (CodexSandboxOnline), и запись в папку .git она блокирует на своём уровне. Симптом:

  Проверено: правами доступа на папку и настройкой writable_roots это НЕ лечится, только сменой режима песочницы.
  Эквивалент той же команды:  codex --dangerously-bypass-approvals-and-sandbox
  install.ps1 (ШАГ 5) дополнительно пропишет в C:\Users\<ты>\.codex\config.toml
        sandbox_mode = "danger-full-access"
        approval_policy = "never"
  Флаги в команде запуска всё равно оставлять: так агент работает, даже если config.toml не подхватился.
