ШАГ 0.5. POWERSHELL 7 — ОБЯЗАТЕЛЬНО
  [ ] winget install --id Microsoft.PowerShell --source winget --accept-package-agreements --accept-source-agreements
      Проверка в новом окне:   pwsh -v   -> 7.x

ШАГ 1. NODE И PNPM
  [ ] Node.js 22 LTS: https://nodejs.org (кнопка LTS), установщик, всё по умолчанию.
      Проверка:   node -v          -> v22.x
  [ ] pnpm 10. Окно PowerShell ОТ ИМЕНИ АДМИНИСТРАТОРА:
                  corepack enable
                  corepack prepare pnpm@10.34.5 --activate
      Проверка (обычное окно):   pnpm -v   -> 10.34.5
  [ГРАБЛИ] Два подвоха. corepack enable пишет в C:\Program Files\nodejs и без администратора падает
  с "EPERM ... pnpx". И pnpm@latest сейчас это 12, а комплект и репетиционное приложение на pnpm 10 —
  версию пиннуем руками, иначе lock-файлы не сойдутся.

  [ ] Лишний пакет:   npm ls -g --depth=0   . Если есть строка node@<версия> — удалить:   npm rm -g node
  [ГРАБЛИ] Глобальный npm-пакет "node" перекрывает настоящий Node: в git-bash pnpm, vercel, codex и claude
  падают с "This: command not found", а в PowerShell работают. Причину ищут долго.

  [ ] npm не обновлять через npm@latest.
  [ГРАБЛИ] npm 12 требует Node >= 22.22.2, на 22.20 отказывается с notsup. Нужно обновить — npm i -g npm@11

  [ ] Проверка входа в GitHub и права записи с этого ноутбука, ничего не отправляется:
      cd C:\hack\lomra
      git push --dry-run origin main
      "Everything up-to-date" -> вход под Alexanderadon, право есть.
      "Repository not found" -> Windows помнит ДРУГОЙ аккаунт GitHub. Посмотреть чей:
          cmdkey /list | Select-String "github"
      удалить и войти заново:
          cmdkey /delete:LegacyGeneric:target=git:https://github.com
      затем повторить clone — откроется окно входа, войти как Alexanderadon.
      403 или "denied" -> входишь под собой, но права нет: писать организаторам.
  [ГРАБЛИ] При чужом аккаунте приватный репозиторий отдаёт именно "Repository not found", а не 403.
  Выглядит как несуществующая ссылка, хотя это отказ в доступе.
